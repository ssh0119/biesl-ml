# 코드 변경 및 결과 해석

## 결론

이번 30-fold 비교에서는 **Plan C 12개 특징 + CNN pooling 256개 특징 → XGBoost**가 가장 좋았습니다. 정확도 **85.59%**, Macro F1 **0.7512**로 기존 단순 평균 대비 **+3.86%p / +0.0740**이며, 6,059개 테스트 윈도우에서 정답이 234개 늘었습니다.

## 구조 변경

기존: 원시 신호 → CNN → 5개 클래스 확률, 생체 특징 → XGBoost → 5개 클래스 확률. 마지막에 두 확률을 평균했습니다.

추가: 원시 신호 → 기존 CNN convolution → 평균 pooling 128개 + 최대 pooling 128개 → 생체 특징 12개와 연결 → 총 268개 특징으로 XGBoost를 새로 학습합니다. CNN은 고정하고, XGBoost만 새로 학습한 두 단계 모델입니다. 두 모델을 동시에 역전파로 학습한 구조는 아닙니다.

96차원 은닉층은 `Linear(256,96)`과 ReLU 이후 값이고, 256차원 pooling은 그보다 앞단 값입니다. 이번에는 256차원 표현이 더 좋은 결과를 냈지만, 더 많은 정보 보존 때문인지는 별도 실험 없이 단정할 수 없습니다.

## 변경 파일과 역할

| 파일 | 변경 내용 |
|---|---|
| `scripts/evaluation/run_cnn_embeddings.py` | 새 실행 파일. 기존 파일 수정 없이 세 가지 특징 결합 실험을 추가 |
| 위 파일의 `extract()` | GPU에서 CNN을 eval 모드로 실행해 96차원 은닉층, 256차원 pooling, 기존 확률을 추출 |
| 위 파일의 `main()` | 체크포인트와 입력 해시 확인, fold별 29개 학습/1개 테스트 확인, XGBoost 90개 학습·저장 |
| 위 파일의 `summarize()` | 6가지 방식의 지표·confusion matrix·예측 CSV·README 생성 |
| `output_new_2/` | 이번 결과, 모델, 특징 순서/중요도, 실행 설정, 보고서 |

기존 `src/cnn/model.py`, `src/plan_c/config.py`, `output_new_1`은 수정하지 않았습니다. CNN 가중치는 `output_new_1/folds/XX/cnn_model.pt`를 참조합니다. 새 XGBoost를 사용할 때는 해당 fold의 CNN과 함께 사용해야 합니다.

## 어떤 클래스가 달라졌나

재현율은 각 실제 클래스의 정답 비율입니다.

| 클래스 | 기존 단순 평균 | 새 268개 특징 XGBoost |
|---|---:|---:|
| rest | 99.56% | 98.82% |
| mental1 | 39.90% | 69.27% |
| mental2 | 61.67% | 55.83% |
| physical1 | 66.11% | 79.50% |
| physical2 | 71.54% | 70.51% |

큰 개선은 mental1과 physical1에서 나타났습니다. 모든 클래스가 개선되지는 않았으며 mental2와 mental1의 혼동은 여전히 남아 있습니다.

## 검증 내역

- 30개 fold 각각의 CNN 원본 학습 목록과 현재 XGBoost 학습 목록이 일치하며, 테스트 녹화는 제외됐습니다.
- 세 가지 방식마다 30개씩, 총 90개 XGBoost 모델을 학습했습니다.
- 각 fold의 CNN 학습·테스트 특징을 같은 체크포인트에서 추출했습니다.
- 학습·테스트를 별도로 추론하고 테스트 배치를 기존 평가와 맞춰, 추출 경로의 클래스 확률이 원본 예측을 재현하는지 확인했습니다.
- 6,059개 녹화/시간 키는 중복 없이 한 번씩 평가됐습니다.
- 예측 CSV에서 6개 confusion matrix를 다시 계산해 저장된 지표와 일치함을 확인했습니다.
- 기준 CNN, XGBoost, 단순 평균의 confusion matrix가 `output_new_1`과 정확히 일치했습니다.
- 코드는 Python 컴파일 검사를 통과했습니다.

## 해석 범위

새 세 가지 후보와 XGBoost 설정은 실행 전에 고정했습니다. 다만 이미 여러 번 살펴본 동일 데이터에서 추가 비교한 것이므로, 85.59%를 새로운 독립 데이터에 대한 보장으로 해석하면 안 됩니다. 현재는 녹화 단위 LORO이고, 새로운 참가자 단위의 독립 평가는 아닙니다.

실행 중 처음에는 전체 윈도우를 한꺼번에 묶어 추출하여 원본 테스트 묶음과 GPU 수치 차이가 발생했습니다. 예측 클래스는 같았고 최대 확률 차이는 약 0.000040이었지만, 묶음을 일치시키고 30개 fold를 처음부터 다시 실행했습니다. 최종 결과는 `output_new_2`에 있으며, 중단된 초기 시도의 4개 fold는 별도 `output_new_2_initial_attempt`에 보관되어 최종 집계에 포함되지 않습니다.
